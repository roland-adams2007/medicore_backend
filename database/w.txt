# 🏥 REAL PATIENT FLOW IN A CLINIC SYSTEM

Yes — **patient MUST be created first inside a clinic.**

Everything else depends on that.

So the correct lifecycle is:

```
1️⃣ Patient Registration (Profile Creation)
2️⃣ Appointment (optional)
3️⃣ Patient Visit (walk-in or from appointment)
4️⃣ Vitals Recording
5️⃣ Doctor Consultation / Diagnosis
6️⃣ Prescription / Lab Request
7️⃣ Billing / Payment
8️⃣ Follow-up Visit
```

So your worry is valid —
👉 **Visit cannot exist without patient profile.**

---

# ✅ Step 1 — Patient Profile Creation (Receptionist)

When patient comes first time:

* Reception creates **patient profile**
* Patient is tied to:

```
clinic_id (REQUIRED)
branch_id (if multi branch)
```

Example real flow:

> John walks into Lagos Clinic Branch A
> Reception creates:

```
patients:
- clinic_id = 1
- branch_id = 3
- name = John Doe
- phone = 080xxxx
```

Now patient exists in system.

No visit yet.

---

# ✅ Step 2 — Appointment OR Walk-In Visit

Two possibilities:

### 🟢 Option A — Appointment First

Patient books:

```
appointments table
```

Later when patient arrives → system creates:

```
patient_visits
```

---

### 🔵 Option B — Walk-In (Very Common in Africa)

No appointment.

Reception directly creates:

```
patient_visits
```

This is **why visit table must not depend on appointment**.

Correct design 👍

---

# ✅ Step 3 — Department Routing (Very Important)

Reception chooses:

* Cardiology
* Dental
* Pharmacy
* Laboratory

So visit record becomes:

```
patient_visits:
- patient_id = 10
- department_id = 2
- visit_status = waiting
```

Doctor dashboard shows:

> 🔔 Waiting Patients Queue

---

# ✅ Step 4 — Consultation Starts

Doctor clicks:

```
Start Visit
```

System updates:

```
visit_status = in_progress
attending_staff_id = doctor_id
```

Then:

* nurse records vitals
* doctor writes diagnosis
* doctor adds prescription
* doctor requests lab

---

# ✅ Step 5 — Billing Happens After or During Visit

Invoice can be:

* consultation fee
* lab test fee
* drug fee
* admission fee

Invoice tied to:

```
patient_id
visit_id
clinic_id
```

Perfect SaaS monetization structure 💰

---

# ⭐ VERY IMPORTANT ARCHITECTURE RULE

👉 **Patient profile is long-term entity**

👉 **Visit is short-term event**

Example:

One patient can have:

* 2024 → malaria visit
* 2024 → dental visit
* 2025 → surgery visit
* 2026 → follow-up

So:

```
patients = 1 row
patient_visits = MANY rows
```

This is correct database normalization.
